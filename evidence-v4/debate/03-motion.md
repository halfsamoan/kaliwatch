# 역할 3 — 모션 설계·반박 1차

검토 범위: `outputs/kali-orbit/studio.js`, `face.js`, `tokens.js`, 현재 스튜디오의 직접 Chromium 실행 및 `motion-storyboard.png`. 코드 수정 없음.

## 결론

**정적 형태를 먼저 바꾸고, 새 행성의 윤곽에서 재질이 드러나는 전환만 추가한다.** 현재 첨부 이미지의 문제를 더 긴 회전·비행·무한 반짝임으로 가리려는 안은 반대한다. 행성의 앞뒤 고리·구면 광원·그림자가 없는 상태에서는 모션이 아이콘의 단순함만 확대한다.

시·분, 공식 드래곤, INFINITY는 제자리. 행성 자체도 같은 위치·같은 기울기를 지킨다. 새 시그니처는 **Orbital illumination — 윤곽에서 재질로**다. 기존 360ms 궤도 정렬에 행성 재질 180–220ms와 앞 고리의 짧은 밝기 전환만 연결한다. 새 반복 효과는 넣지 않는다.

## 발견 / 근거

1. **현재 행성은 화면 상태 전환과 전혀 연결되지 않은 스티커에 가깝다.**
   - `face.js:25`: `#ringed-planet`의 타원·원·초승달 path가 AOD와 Active에 같은 값으로 들어간다.
   - `studio.js:26–29`: 트랙 목록에 `cosmos`나 `ringed-planet`이 없다.
   - 직접 실행: AOD→Active 0/90/180/360ms에서 행성 opacity=1, 같은 transform matrix, 같은 바운딩박스가 유지됐다. 이는 오작동이 아니라 현재 설계의 결과다.
   - 기존 storyboard를 직접 보면 행성의 광량·재질도 거의 같아 드래곤과 숫자의 점등과 분리돼 보인다. 이 부분은 시각 판단이다.

2. **시간의 연속성은 이미 좋으므로 훼손하면 안 된다.**
   - `studio.js:31–52`: 전환 중 현재 스타일을 읽고 공통 DOM을 patch한다.
   - 직접 실행 0/90/180/360ms에서 `#time`은 같은 노드이고 bounds도 동일했다.
   - 해당 실행의 x/y/w/h는 `[625.1862,385.8147,209.9089,105.9678]`로 네 프레임 모두 같았다. 브라우저 1440×1100 환경의 관측값이며 기기 크기 수치가 아니다.

3. **기존 모션은 90–180ms에 대부분의 읽는 정보가 이미 도착한다.**
   - 직접 실행 90ms: 시간 fill `rgb(222,231,219)`, Active 궤도 opacity `0.764865`, telemetry `0.196589`.
   - 180ms: 시간 최종 fill `rgb(239,248,236)`, 궤도 `0.961383`, telemetry `0.944863`.
   - 360ms: 모두 최종 값. 따라서 새 행성을 600–1000ms 동안 늦게 띄우면 현재의 빠른 계기판과 리듬이 어긋난다.

4. **반전·Live tick 기반은 유지 가치가 있다.**
   - `studio.js:48–71`: 현재 computed style을 시작점으로 삼는다.
   - `studio.js:84`: Live tick은 `render(false,true)`로 진행 중 효과를 보존한다.
   - 이번 역할에서는 해당 구현을 읽었고 기본 전환 프레임을 확인했다. 20회 반전·전체 회귀 재실행은 하지 않았으며 다른 Verifier의 새 결과를 기다린다.

## 추천 시그니처 — Orbital illumination

### 레이어 계약

- `planet-silhouette`: AOD에도 보이는 얇은 외곽·terminator. 최종 위치 고정.
- `planet-material`: 구면 명암·아주 낮은 대비의 대기 띠 또는 정적 표면. AOD `opacity=0`/hidden, Active에만 등장.
- `ring-back`: 뒤쪽 고리. 본체 뒤로 정확히 가려지는 정적 형태.
- `ring-front`: 앞쪽 고리. 재질이 드러날 때 약하게 밝아진다. 고리와 본체에 서로 다른 회전을 적용하지 않는다.
- `planet-rim`: 가장 밝은 얇은 편측 림. 고정된 광원 방향, AOD에서는 낮은 밝기.

행성 레이어 ID와 child 구조는 두 상태에서 동일하게 유지한다. opacity/visibility만 달라야 한다. AOD용으로 임의의 다른 행성 그림을 끼워 넣지 않는다.

### 프레임 명세 — 제안이며 미구현

| 시점 | 행성 | 시간·나머지 화면 |
|---|---|---|
| 0ms | 같은 실루엣·고정 기울기. 재질은 아직 어두움 | AOD 시각은 읽을 수 있고 위치 그대로 |
| 90ms | 본체 재질이 드러나는 중. 앞 고리는 뒤 고리보다 선명해지기 시작 | 기존 숫자는 거의 밝아짐. telemetry는 등장 초반 |
| 180ms | 구면 명암·앞뒤 고리가 거의 완성. 별은 그대로 | 상태값은 대부분 읽힘 |
| 360ms | 완전히 정지. 잔여 glint·흔들림 없음 | 외곽 궤도도 정렬 완료 |

- 본체 재질: 180–220ms, `cubic-bezier(.22,1,.36,1)`.
- 앞 고리: 40ms 지연 +180ms opacity. 핵심 정보 지연이 아니라 장식의 깊이 구분이다.
- rim: 220ms opacity. 밝은 선을 움직이거나 행성 둘레를 빙 돌리지 않는다.
- Active→AOD: 140–180ms에 재질을 비표시. 시각은 항상 고정.
- 복귀 전체는 기존 360ms를 넘기지 않는다. 버튼·focus는 즉시 반응한다.
- 저감 모션은 최종 opacity·visibility를 즉시 적용한다.

opacity를 사용한다고 SVG가 모든 브라우저에서 GPU 합성만 한다고 보장할 수 없다. 실제 워치의 성능·전력은 미확인이다. 동적 SVG 필터·grain·displacement를 매 프레임 계산하지 말고 정적인 재질로 만들어 둔다.

## 대안 — Micro-parallax arrival

행성 전체가 최대 `(2px,-1px)`에서 제자리로 돌아오는 220ms transform과 opacity를 사용할 수 있다. AOD 실루엣에서 Active의 물성이 약하게 떠오르는 인상을 준다. 본체와 앞뒤 고리는 반드시 하나의 부모 transform 아래에서 같이 움직인다.

**우선순위는 낮다.** 450 좌표의 2px 이동은 225px 검토에서 약 1px라 효과가 미약할 수 있고, 더 크게 움직이면 이미 안정적인 드래곤·시각과 비교해 행성만 튀어나온다. 새로 등장한 자산처럼 보이면 공유 형상 원칙에도 맞지 않는다. 처음부터 모션을 넣기보다 정적 최종안으로 충분한지 먼저 비교해야 한다.

## 다른 안에 대한 반박

- **행성을 크게 회전시키자는 안:** 구면은 돌면서 앞뒤 고리 기울기를 바꾸지 않는다. 고리·광원·본체가 한꺼번에 회전하면 자연 천체보다 UI 로딩 스피너로 읽힌다. 같은 워치를 반복해서 깨울 때 피로가 커진다.
- **행성을 화면 바깥에서 날려 넣자는 안:** 기존 AOD에 같은 위치의 실루엣이 있는 상황과 충돌한다. AOD→Active는 새로운 화면 소개가 아니라 같은 시계의 상태 복귀다.
- **블랙홀·행성·별·외곽 궤도를 동시에 움직이자는 안:** 사용자 불만은 단순한 형태다. 새 모션 수가 형상 품질을 증명하지 않는다. 한 시그니처에 비용을 집중해야 한다.
- **모션을 전부 없애자는 안:** 시간 고정과 낮은 주변 움직임을 양립시킬 수 있다. 사용자가 이미 AOD 복귀 연출을 요청했으므로 기존 360ms 단발 정렬은 적절한 정체성 장치다.

## 이 추천이 틀릴 수 있는 조건

1. 최종 구도가 커다란 수평선·행성의 일부로 바뀌어 앞뒤 고리가 보이지 않으면, 고리 점등 대신 편측 대기 림의 opacity만 쓰는 편이 낫다.
2. 225px에서 재질 계층이 보이지 않고 흐릿한 얼룩만 된다면 모션보다 재질을 삭제하고 선명한 구면 그림자·림만 남겨야 한다.
3. 공식 드래곤과 행성의 시각적 경쟁이 커지면 행성의 점등을 더 낮추거나 제거해야 한다. 시간과 드래곤을 희생해 행성을 주인공으로 만들지 않는다.
4. 실제 장치에서 SVG opacity 레이어가 과도한 재래스터 비용을 보이면 단순 리소스 crossfade 또는 고정 최종 그림으로 줄여야 한다.

## 위험 / 권장 검증

- 급반전: snapshot에 새 레이어 opacity/visibility를 포함. 새 회전 시작값을 매번 강제하지 않는다.
- 저감 모션: 진행 중·140ms 예약 중 각각 켜서 효과/예약이 0개인지 확인한다.
- Live tick: 새 그라데이션·path·마스크 수가 상태마다 달라져 patch가 subtree를 교체하지 않는지 확인한다.
- AOD: 큰 본체의 nonzero 면적을 그대로 남기지 말고 재질을 비표시한다. 발광 비율은 새 래스터에서 다시 계산한다.
- 검수: 0/90/180/360ms, 225px/450px, 자연 종료·중간 반전 뒤 정적 기준 픽셀 비교.

**1차 판정:** 기존 연속성 구조는 유지 승인. 행성 시각 품질의 근본 교체 전에는 새 모션을 늘리는 안을 승인하지 않는다. 정적 최종안이 확정된 뒤 위의 작은 재질 점등만 조건부 권장한다. 교차 반박 라운드 대기.

## 교차 반박 — A 작은 실물형 행성 vs B 큰 cropped 관측창

전달받은 구도는 A `(350,112), r32, 고리54×17`, B `(475,107), r144, 고리의 밝은 부분은 x320보다 왼쪽 금지`다. 아래는 후보 렌더를 보기 전의 **설계 반박**이며 렌더 품질 승인으로 간주하지 않는다.

### A에 대한 반박

작은 행성의 재질이 충분히 정교하면 기존 아이콘보다 크게 좋아질 수 있다. 하지만 225px에서 본체 반지름은 16 CSS px다. 전달된 고리 54×17이 반지름(rx/ry)을 뜻한다면 투영 전체는 약 54×17 CSS px이며, 전체 폭·높이를 뜻한다면 그 절반이다. 어느 경우든 작은 띠이므로 미세 재질 점등·앞뒤 고리의 차이가 눈에 남지 않을 수 있다. 작은 형태에 회전까지 넣으면 로딩 표시나 두 번째 브랜드 배지처럼 보인다.

특히 고리의 왼쪽 범위는 기울기 적용 전에도 x296 근방까지 오므로 드래곤 꼬리·머리와 붙는 듯한 연결이 생길 수 있다. 현재 사용자 첨부가 보여 준 바로 그 '용 옆에 붙인 작은 아이콘' 구도를 더 정교하게 만드는 데 그칠 위험이다.

**A를 택한다면:** 행성 본체·그림자만 180ms 안에 점등하고 고리와 실루엣은 정지시킨다. 앞 고리의 지연도 생략할 수 있다. 전체 행성을 translation/rotation으로 움직이는 대안은 철회한다. 225px에서 정교한 앞뒤 가림이 실제로 보이지 않으면 A는 탈락시켜야 한다.

### B에 대한 반박

큰 cropped 행성은 독립 아이콘이 아니라 화면의 공간적 배경이 되어 더 성숙한 방향일 수 있다. 그러나 매우 밝은 림과 고리를 쓰면 드래곤과 행성이 서로 주인공 자리를 다투며, 시간보다 먼저 거대한 천체를 보게 된다. 큰 면적에 광원이 켜지는 전환은 작은 행성보다 훨씬 쉽게 플래시처럼 보인다.

B의 크기만으로 프리미엄이 되는 것은 아니다. x331 부근의 왼쪽 실루엣이 단순한 큰 원호로만 보이면 현재의 초승달 아이콘을 확대했을 뿐이다. 구면 명암·광원·고리 가림이 정적 화면에서 성립해야 한다.

**B를 택한다면:** AOD는 본체 면적을 비표시하고 편측 림·고리 일부만 남긴다. Active에서는 낮은 대비의 큰 본체를 180–220ms opacity로만 드러낸다. 행성·고리의 위치·각도·크기는 고정한다. 밝은 고리나 음영 경계가 시간·드래곤으로 들어오는 x320 이하 구역을 침범하지 않게 한다. AOD→Active의 큰 행성 점등을 기존 -14도 외곽 정렬보다 더 강한 모션으로 만들지 않는다.

### 위치별 프레임 차이

| 시점 | A 작은 행성 | B cropped 관측창 |
|---|---|---|
| 0ms | 기존 위치의 작은 림과 뒤 고리 | 큰 면은 검정. 같은 위치의 얇은 편측 림만 남음 |
| 90ms | 본체 명암만 먼저 읽힘. 링 움직임 없음 | 어두운 구면의 깊이가 드러남. 림은 번쩍이지 않음 |
| 180ms | 사실상 최종 상태. 더 늘리면 작은 배지에 주의를 낭비 | 면과 그림자가 안정됨. 앞 고리 점등도 종료 |
| 360ms | 추가 변화 없이 정지 | 기존 계기 궤도까지 정렬 완료, 모두 정지 |

### 최종 모션 추천

**두 안 중에는 B의 절제된 재질 점등을 우선 추천한다.** 이유는 사용자가 거부한 작은 아이콘 구도 자체를 바꾸고, 행성을 화면의 공간으로 통합할 수 있기 때문이다. 이 추천은 구도 판단이며 아직 후보 이미지를 보지 않았으므로 조건부다.

단, B가 225px에서 모호한 원호/밝은 얼룩이 되거나 드래곤보다 강해지면 A의 정적 재질형 또는 행성 없는 정밀 궤도 안이 낫다. 최종 선택에서는 새 모션의 수보다 **정지된 첫 화면의 완성도와 두 주인공 경쟁 여부**를 우선해야 한다.

새 행성 레이어의 반전은 opacity 하나를 중심으로 설계한다. 고리·구체를 따로 공간 이동시키지 않으므로 앞뒤 가림은 모든 중간 프레임에서 일관된다. 이는 촉각 없는 브라우저에서도 저감 모션과 Live tick 안정성을 가장 쉽게 유지하는 방식이다.
