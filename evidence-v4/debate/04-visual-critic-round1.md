# 역할 4 — 반대측 시각 Critic

## 판정

**현재 B는 그대로 채택하지 않는다. B의 구도를 수정한 다음 재검수한다.** 목표에 가장 가까운 것은 B지만, 큰 재질을 넣었다는 이유로 작은 시계의 정보 위계를 희생하면 안 된다. 이는 다수결 판단이 아니라 실제 렌더와 영역별 픽셀 비교에 근거한다.

직접 본 파일: `work/v4-proposals/gallery.png`, `A-active.png`, `B-active.png`, `C-active.png`, 현재 v3의 `outputs/kali-orbit/preview-active.png`. 원본 코드·후보는 수정하지 않았다.

## 발견 / 근거

### 1. B는 '우주를 보는 창'이지만 고리가 시간 영역까지 들어온다 — 현재 차단

450px B 렌더에서 큰 앞 고리는 시각 오른쪽 8의 상단·오른쪽 배경까지 내려온다. 날짜와 브랜드 오른쪽에도 밝은 선·면이 들어와, 시간과 용 다음에 읽혀야 하는 배경이 문자 주변의 대비를 바꾼다. 글자를 지우거나 읽지 못하게 했다는 주장은 아니다. **읽는 영역을 비워 둬야 한다는 설계 계약을 어겼다는 것**이 문제다.

`celestial.js:5` B의 중심 `(458,102)`, r126, tilt -26°와 `:13`의 고리 바깥 반지름 `1.95r` 조합이 밝은 고리를 시각 쪽으로 확장시킨다. x축 fade만으로는 아래쪽 침범을 막지 못한다.

같은 450×450 Chromium 렌더에서 `#cosmos`를 제거한 버전과 원본의 RGB를 비교했다. 모든 항목은 사각 보호영역 안의 배경 변화이며, glyph 손상이나 실제 시선 측정이 아니다.

| 후보 | 시각 보호영역 x100..344, y194..270 | 날짜 x145..305, y160..190 | 브랜드 x150..300, y138..163 |
|---|---:|---:|---:|
| A | 변경 0px / 최대 채널 차이 0 | 0 / 0 | 121 / 65 |
| B | **1,745px / 최대 137** | **1,183 / 78** | **684 / 101** |
| C | 0 / 0 | 0 / 0 | 19 / 18 |

드래곤 사각 프레임 안에서도 A 1,194px, B 921px, C 669px가 바뀐다. 이 사각 프레임에는 드래곤이 차지하지 않는 여백도 있으므로 이 수치를 로고 오염 면적으로 해석하지 않는다. 시각적으로 A의 행성 왼쪽 링이 용 꼬리와 붙어 보인다는 관찰을 보조할 뿐이다.

### 2. B의 질감은 풍부하지만 기계적으로 반복된다 — 수정 권고

`celestial.js:15–24`는 고리 72개와 표면 띠 24개를 일정 간격으로 생성한다. 물질감이 v3보다 확실히 좋아졌지만 B에서는 고리가 나이테·지문 같은 촘촘한 패턴으로 읽히는 부분이 있다. 표면 띠도 고른 간격의 대각선 줄무늬가 돼 큰 구면의 부드러운 광원보다 먼저 읽힐 위험이 있다.

225px에서 고리 간격은 대략 0.68 CSS px 수준으로 줄어든다. 실제 기기의 moiré가 발생했다고 주장하지 않는다. 미세 패턴이 저해상도 축소에서 주된 인상이 될 수 있다는 디자인 위험이다.

### 3. A는 입체감 개선이 분명하지만 구도 문제는 남는다

구체·앞뒤 고리·그림자가 보여 v3의 모호한 초승달 문양보다 확실히 낫다. 시간 보호영역 침범도 없다. 다만 드래곤 오른쪽에 작은 완성된 물체를 붙인 구조는 같다. 사용자의 “더 업데이트”를 단순히 고급 아이콘 교체로 해석할 위험이 있다. 좁은 공간의 실제 워치에서 B가 실패할 때는 합리적인 대안이다.

### 4. C는 이번 요청에 가장 약하다

C는 가볍고 차분하지만 주요 형태가 또 원호와 선이다. 첨부한 v3의 단순함을 반려한 요청에 비춰, 추상적인 선을 조금 더 정밀하게 그린 것으로 받아들여질 수 있다. 이는 기술 결함이 아니라 요청 충족에 관한 판단이다. 이번 기본안으로는 추천하지 않는다.

## 추천과 반박 가능한 조건

**수정한 B를 우선 검토한다.** 그러나 다음 조건 중 하나라도 충족하면 A가 더 낫다.

1. B를 보호영역 밖으로 물리면 큰 행성의 구면·고리 관계가 사라지고 단순 원주선만 남는다.
2. 재질 밝기를 낮췄을 때 225px에서 큰 행성의 존재가 모호해지고 정보 위계만 불안정하다.
3. 재질을 제대로 보이게 하려면 시각보다 큰 밝은 면적이 반드시 필요하다.
4. AOD에서 B가 정교한 형상이 아닌 겹친 좌표계처럼 보인다.

그 경우 A의 지름 80→90 정도는 비교할 수 있지만, 용과 고리가 붙는 경계를 해결해야 한다. 장식을 늘려 디테일을 증명하려 하지 말고 몸체의 구면 명암과 링의 앞뒤 관계를 남긴다.

반대로 A가 225px에서 작은 배지로만 보이고 B가 보호영역을 지키면서 깊이를 유지한다면, A를 고집할 근거가 없다. 최종 결정은 수정 렌더로 판단한다.

## 위험 / 미확인

실제 시선 추적·실기 밝기·배터리·WFF 자원 비용은 이번 역할에서 검증하지 않았다. 위 영역 비교는 Chromium의 같은 크기 원본 PNG에 한정된다. pixel 변화가 0이라고 미학적으로 우수하다는 의미도 아니다. 실제 구현의 360ms 모션 검수는 새 레이어 통합 이후 별도로 해야 한다.
